# Правки після приймання

Три зауваження з живого користування, 10.09.2026. Діагноз по кожному вже є —
причини знайдені в коді, не треба шукати з нуля.

---

## 1. Нечитабельний текст у формі заявки оренди

**Симптом.** `/admin/rental-applications/:id`, вкладка «Сторони»: значення в картці
`ОРЕНДОДАВЕЦЬ` (П.І.Б., ІПН, адреса, телефон, e-mail, адреса складу) майже не видно —
темний текст на темному тлі. Сусідня картка `ОРЕНДАР` читається нормально.

**Причина.** `components/rental/RentalPartiesSection.jsx` не змінювався з червня
2026 — це один із файлів, що потрапили в борг «форма заявки оренди». CSS форми
справді переведено на токени, але **проблема не в CSS, а в JSX**: компонент
побудований на inline-стилях із літералами.

```
рядок 45   border: '1px solid #ddd'
рядок 71   borderTop: '1px dashed #eee'
рядок 79   borderBottom: '1px dashed #ddd'
рядок 86   borderBottom: '1px dashed #ddd'
рядок 90   color: '#e53e3e'
рядок 101  border: '1px dashed #ddd', color: '#888'
```

Ці значення розраховані на світле тло. У темній темі `#888` на темному — саме той
«темно-синій, якого не видно», а `#ddd`/`#eee` дають світлі рамки там, де їх бути
не повинно.

**Що зробити.** Прибрати всі inline-стилі з `RentalPartiesSection.jsx`, перевести на
токени й класи. Потім пройтись рештою компонентів форми заявки тим самим оком —
`RentalItemCard`, `RentalItemsSection`, `RentalKitItemsList`, `RentalTotalsBlock`,
`RentalDocumentTab`, `UpsellPanel`, `ProductSearchBar`, `RentalFormHeader`,
`RentalFormTabs`, `RentalApplicationPrint` (у друкованої форми літерали доречні —
вона друкується на білому, її не чіпати). Критерій: `grep -nE "style=\\{\\{"` по теці
`components/rental/` порожній, окрім друкованої форми.

Перевірити візуально в **обох** темах.

## 2. Заявка `RA-2026-036` у списку угод

**Симптом.** У списку угод висить рядок `RA-2026-036` від 09.09.2026: клієнт `—`
(хоча телефон є), чип `магазин`, позиція «Шурупокрут Dnipro-M CD-12QX», статус
`Повернено`, «Оренда до» порожня. Видалити не можна, а клік відкриває не картку
угоди, а стару форму заявки.

**Причина.** Це одна з 11 заявок оренди без прив'язаної угоди, які свідомо лишили
видимими, щоб вони не зникли зі списку. Рішення було правильне — але рядок
показується так, ніби це звичайна угода, і поводиться інакше.

**Три окремі баги в одному рядку:**

1. **Чип `магазин` для орендної заявки.** «Шурупокрут Dnipro-M CD-12QX» — орендний
   інструмент. Визначення типу не розпізнає позиції заявки так само, як позиції
   угоди. Це справжня помилка, не косметика: перевірити, як `getAllDealRows()`
   рахує тип для рядків-заявок.
2. **Статус `Повернено` в колонці статусу угоди.** `Повернено` — зі словника
   оренди, а колонка показує статус угоди. Для рядка-заявки колонка має брати
   `RENTAL_STATUS`, не `ORDER_STATUS`.
3. **Клієнт `—` при наявному телефоні.** Заявка зберігає `clientName` окремо від
   `Client`; якщо прив'язки немає, рядок має показувати ім'я із самої заявки.

**Що зробити з самим рядком.** Він має виглядати як те, чим є:

- окремий чип `заявка` замість `магазин`/`оренда`, у нейтральному тоні;
- статус зі словника оренди;
- у колонці дій — `Створити угоду` (заявка стає угодою, номер угоди присвоюється,
  рядок зникає зі списку осиротілих) і `Видалити` з `ConfirmDialog`;
- клік по рядку веде на форму заявки — це поки нормально, але в підказці колонки
  має бути видно, що це заявка без угоди.

**Що зробити зі станом загалом.** 11 таких заявок — це залишок старої схеми, де
заявка існувала окремо. Правильний фініш: конвертація броні з календаря створює
**угоду**, а не заявку; наявні 11 розбираються кнопкою `Створити угоду`; коли
осиротілих не лишається — маршрут `/admin/rental-applications/:id` і форма
видаляються. Це закриває борг, записаний у `04-release.md`.

## 3. Календар: у вкладці «Зайняті» не видно, хто що зайняв

**Симптом.** У колонці «Інструмент» майже всі рядки показують лише код
(`PP-T8H8Q`, `PP-VHQMB`, `PP-8DDWY`), а не назву. Смужки бронювань вузькі, ім'я
клієнта обрізане до «Полі», «Фесе», «Прит». Щоб зрозуміти рядок, треба клікати.

**Причина назви.** `pages/RentalCalendar.jsx`, рядок 125:

```js
const list = await productsApi.list({ isRent: true });
```

Без `includeHiddenRent: true`. Тому в `productById` потрапляє не весь парк, і в
`buildTimelineRows` (`model/calendarTimeline.js`, рядок 106) `product?.name`
не резолвиться для решти. Додати прапорець — календар має бачити всі орендні
картки, зокрема приховані з публічного каталогу, бо зайнятість від видимості на
сайті не залежить.

**Причина обрізаних імен.** Діапазон лише місячний: одноденна оренда на місячній
шкалі — це ~30 px, туди не влізе жодне ім'я. У специфікації був перемикач
діапазону, він не реалізований.

**Що зробити:**

1. Додати `includeHiddenRent: true` і перевірити, що назви з'явились у всіх рядках.
2. Перемикач діапазону `Тиждень` · `2 тижні` · `Місяць`, **за замовчуванням
   Тиждень** — на тижневій шкалі смужка вміщує текст.
3. Смужка показує `клієнт · № угоди`, у `title` — повний текст плюс дати, щоб
   наведення відповідало на питання без кліку.
4. Мінімальна ширина смужки, щоб одноденна бронь не сплющувалась у пляму.
5. Рядок інструмента: назва першим рядком, `інв. № · SKU` другим, моно — як у
   решті таблиць.
